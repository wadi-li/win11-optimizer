Как включить кнопки «Проанализировать» и «Применить»1 раз, 1 минута

Страница в интернете (GitHub или pplx.app) не может запускать программы на компьютере — браузер это запрещает. Поэтому скрипт сам запускает эту же страницу у вас на ПК, но уже с рабочими кнопками. Сервер слушает только адрес 127.0.0.1 (недоступен из сети) и принимает команды только со случайным ключом, который выдаётся при каждом запуске.

Запуск

1. Скачайте архив Win11Toolkit.zip (в нём Start-Toolkit.cmd, Win11-BootRamBattery-Toolkit.ps1 и index.html) и распакуйте в любую папку, например C:\Users\<вы>\Downloads\Win11Toolkit.
2. Дважды щёлкните Start-Toolkit.cmd и подтвердите запрос UAC (права администратора нужны для применения; без них работает только анализ).
3. Браузер откроется сам по адресу вида http://127.0.0.1:порт/?t=ключ. Индикатор вверху станет зелёным.
4. Не закрывайте окно PowerShell, пока работаете. Завершить — кнопка «Остановить панель» или Ctrl+C в окне.

Что работает без скрипта

• Шаг 2 — загрузка JSON-оценок, созданных скриптом (Start-Toolkit.cmd -Mode Collect).
• Шаг 3 — просмотр плана и готовая команда для выбранных пунктов (копируется в буфер).
• Шаг 4 — сравнение «до/после» двух загруженных JSON и экспорт в CSV.
Отдельные файлы: ps1, cmd, index.html.

Причина №1: последовательный запуск автозагрузки Run с шагом ≈30 с (+112 … +429 с после входа)

          

            Посмотрите на метки времени старта в таблице ниже: eguiProxy стартует в 16:03:40.0, ровно через 30.1 с стартует Everything (16:04:10.1), ровно через 30.1 с — OODefragTray (16:04:40.2), ещё через 30.5 с — Adguard (16:05:10.7), ещё через 30.1 с — AdGuardVpn (16:05:40.8), затем интервалы становятся неравными: OneDrive (16:06:08.7, +27.9 с), AutoDarkModeSvc (16:06:25.8, +17.1 с), NLClientApp (16:06:55.9, снова ровно +30.1 с), Grammarly.Desktop (16:07:05.6, +9.7 с) и TheBat64 (16:08:26.5, +80.9 с); последние процессы автозагрузки появляются к +428.9 с.

Механизм ожидания журналами не подтверждён и в документации Microsoft не описан — точную причину покажет трасса загрузки (-Mode BootTraceStart). Независимо от механизма, каждая убранная из автозагрузки программа сокращает очередь.
          

        


        

          
Причина №2: Сбойные ядерные драйверы (Event ID 7026) и падение службы Samsung (Event ID 7034)

Его не трогаем. Длительность задержки от ошибки 7026 журналом не измеряется — нужна трасса WPR.

            Следом в 15:56:59 служба SamsungMagicianSVC принудительно устанавливает драйвер MagicianSataModeReader (Event ID 7045), а в 15:57:00 служба CMigrationService аварийно падает (Event ID 7034).

        Почему 16 ГБ ОЗУ на T14S не хватает и как работает лимит выделенной памяти (Commit Limit)
        Текущий pagefile.sys: жёстко задан 8 192 МБ
      

      

        В реестре вашего ноутбука (HKLM\...\Memory Management\PagingFiles) сейчас прописано жёсткое ограничение: c:\pagefile.sys 8192 8192 (ровно 8 ГБ). В 64-битной Windows 11 26H2 действует строгая формула диспетчера виртуальной памяти:
        Commit Limit (24 328 МБ) = Видимое ОЗУ (16 136 МБ) + Файл подкачки (8 192 МБ).
      


      

        

          
Главный секрет нехватки памяти при распаянных 16 ГБ

          

            Программы САПР (Altium Designer, AutoCAD, DipTrace с 3D-моделями STEP), браузеры и системные службы запрашивают у ядра Windows гарантированный резерв виртуальной памяти (Private Commit Charge). Даже если физическое ОЗУ занято всего на 75% (за счёт сжатия Memory Compression, которое сейчас держит 1 215.1 МБ), как только сумма Committed Bytes упирается в потолок 24 328 МБ, Windows выдаёт ошибку нехватки памяти и аварийно закрывает вкладки или САПР!

            Прямо сейчас в спокойном состоянии на вашем T14S уже выделено 14 180 МБ Commit (из них 1 662.7 МБ зарезервировал один только AdGuard, 1 300.1 МБ — 6 процессов TheBat64, 770.7 МБ — AdGuard VPN, 504.1 МБ — OneDrive, 500.2 МБ — Grammarly + WebView2). До жёсткого потолка остаётся всего 10.1 ГБ!
          

        


        

          
Инженерное решение для диска C:\ (NVMe 930 ГБ, свободно 482.9 ГБ)

          

            1. Очистка фонового резерва (Вкладка 2): Выгрузка фоновых пожирателей (AdGuard VPN, Grammarly+WebView2, Autodesk Access, Phone Link, Виджеты, Intel DSA) мгновенно освобождает ~3.7 ГБ Commit Charge и ~2.9 ГБ физического ОЗУ.

            2. Расширение pagefile.sys до 16 384 МБ (Исходный) — 24 576 МБ (Максимальный): За счёт установки исходного размера 16 384 МБ (16 ГБ) файл подкачки выделяется одним непрерывным блоком на NVMe SSD без фрагментации, а общий лимит Commit Limit возрастает с 24.3 ГБ до 32.5–40.5 ГБ! При наличии 482.9 ГБ свободного места на диске C: это даёт абсолютный запас прочности для тяжёлых САПР.

        Оптимизация времени работы от батареи и спящего режима на Lenovo ThinkPad T14s Gen 1
        BIOS: N2YET49W (1.38) • Режим: S0 Low Power Idle (Network Connected)
      

      

        По данным команды powercfg /a и системного журнала вашего T14S выявлены две группы потерь заряда батареи: 1) высокий фоновый расход во время работы и 2) разряд в спящем режиме Modern Standby (S0ix) с активной сетью.
      


      

        

          
1. Почему батарея быстро садится во время активной работы

          

            За текущую двухчасовую сессию на вашем ноутбуке четыре фоновые утилиты впустую сожгли более 2 400 секунд (40 минут!) чистого процессорного времени Core i7-10510U, не давая ядрам уходить в глубокие C-состояния (C8/C10):

            • Grammarly.Desktop + Superhuman.WebUI + 6x WebView2: 1 137.1 с CPU (постоянный глобальный перехват окон UI Automation)

            • AdGuard VPN (клиент + служба): 550.9 с CPU

            • OneDrive (клиент + служба): 365.4 с CPU

            • AdGuard (блокировщик): 353.4 с CPU

            • logioptionsplus_agent + AdskIdentityManager + CrossDevice: ещё 438.5 с CPU.

            Выгрузка только этих фоновых процессов снижает энергопотребление ноутбука в простое/чтении схем с 9–12 Вт до 4.5–6.0 Вт (прирост времени работы от батареи на +1.5...2.5 часа)!
          

        


        

          
2. Уникальное преимущество вашего ThinkPad T14s Gen 1 (BIOS N2YET49W): возврат аппаратного сна S3!

          

            Сейчас вывод powercfg /a на вашем T14S показывает:

            Standby (S0 Low Power Idle) Network Connected — Включено

            Standby (S3) — Прошивка не поддерживает этот режим.

            В режиме S0 Network Connected ноутбук во сне продолжает поддерживать Wi-Fi, принимать пакеты и будить процессор, теряя по 10–25% заряда за ночь.

            Но в Lenovo ThinkPad T14s Gen 1 (в отличие от более новых ноутбуков!) в BIOS есть штатный переключатель аппаратного сна S3:

            При перезагрузке нажмите F1 (вход в BIOS Setup) → Config → Power → Sleep State и переключите значение с Windows 10 / Windows 11 на Linux (затем F10 Save & Exit). После этого прошивка N2YET49W включает классический глубокий аппаратный сон S3 (Suspend-to-RAM), где процессор и Wi-Fi полностью обесточены, а питание подаётся только на микросхемы ОЗУ (расход падает до <0.3% в час!).

        Диагностика и оптимизация стационарной рабочей станции BIG (ASUS)
        Поддержка локального сбора JSON за 10 секунд
      

      

        При попытке удалённого вызова команд на компьютере BIG (ASUS) системный агент вернул статус: the Windows sandbox is not provisioned (на BIG включён коннектор в списке устройств, но ещё не инициализирована локальная песочница удалённого выполнения PowerShell). Поэтому мы подготовили для вас автономный скрипт Win11-BootRamBattery-Toolkit.ps1, который запускается на BIG локально в один клик и формирует полный файл Win11-Telemetry_BIG.json для загрузки прямо в это окно!
      


      

        

          
Как проверить BIG (ASUS) за 30 секунд и загрузить данные сюда

          

            1. Скачайте архив Win11Toolkit.zip (скрипт, Start-Toolkit.cmd и эта страница для веб-панели) и распакуйте в одну папку.

            2. Запустите на компьютере BIG двойным щелчком Start-Toolkit.cmd — откроется веб-панель; нажмите в ней «Проанализировать систему» (права администратора скрипт запросит сам через UAC). Консольное меню: Start-Toolkit.cmd -Mode Menu.

            3. Или перенесите созданный файл Win11-Telemetry_BIG_….json сюда кнопкой «Загрузить файл оценки» в панели управления.

            4. Анализатор мгновенно отобразит все процессы, службы, зависимости, ошибки загрузки Event ID 100–106 и настройки памяти компьютера BIG!
          

        


        

          
Ключевые отличия настройки стационарной станции BIG от ноутбука T14S

          

            • Питание и процессор: На стационарном ПК BIG (платформа ASUS) не требуется экономить батарею или отключать сеть во сне, но критически важно исключить фоновые хуки (Grammarly.Desktop, Autodesk Access, ASUS Armoury Crate / Aura lighting services, если они установлены), чтобы снизить DPC-латентность и обеспечить максимальный буст ядер в САПР и компиляции.

Ошибка «файл не содержит цифровой подписи»

        

          Windows помечает скачанные файлы как полученные из интернета, и при политике RemoteSigned (по умолчанию в PowerShell 7) запуск .\файл.ps1 блокируется. Политику выполнения в системе менять не нужно — достаточно одного из вариантов:

          • снять отметку с конкретного файла: Unblock-File .\Optimize-Win11-26H2-Custom.ps1;

          • или запустить с разовым обходом только для этого процесса: powershell -NoProfile -ExecutionPolicy Bypass -File .\Optimize-Win11-26H2-Custom.ps1.

          Для основного скрипта Win11-BootRamBattery-Toolkit.ps1 проще всего использовать Start-Toolkit.cmd рядом с ним.
